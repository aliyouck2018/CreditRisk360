Comment fonctionne CreditRisk360 ?

DONNÉES SYNTHÉTIQUES — PROJET DE DÉMONSTRATION

CreditRisk360 transforme les données de prêts en indicateurs, analyses et alertes qui permettent de mieux comprendre la santé d'un portefeuille de crédit.

Cette démonstration utilise des données synthétiques conçues pour reproduire des situations plausibles d'analyse du risque de crédit. Aucun portefeuille bancaire réel ni aucune donnée client réelle n'est utilisé.

Le principe en quelques secondes

L'idée est simple : une institution financière possède un portefeuille de prêts. CreditRisk360 analyse les informations disponibles sur ces prêts afin d'identifier les tendances, les retards de paiement, les concentrations de risque et les signes de dégradation.

Pourquoi analyser le risque de crédit ?

Lorsqu'une banque ou une institution financière accorde un prêt, elle accepte le risque que l'emprunteur ne rembourse pas comme prévu.

L'objectif de l'analyse du risque de crédit n'est donc pas simplement de savoir combien d'argent a été prêté. Il faut également comprendre :

  • ce qui reste à rembourser ;
  • quels emprunteurs présentent des retards ;
  • quels secteurs ou pays concentrent le risque ;
  • si la situation se dégrade avec le temps ;
  • quels dossiers méritent une investigation plus approfondie.

Les indicateurs expliqués simplement

Pour chaque indicateur : la question métier, l'explication, un exemple — puis la définition technique exacte utilisée par l'application, repliable.

💰 Exposition

Combien d'argent reste actuellement engagé dans les prêts ?

L'exposition correspond au montant qui reste à rembourser sur les prêts en cours. CreditRisk360 utilise systématiquement cet encours restant — jamais le montant initial du prêt.

Exemple

Une banque accorde un prêt de 100 M XAF. Le client a déjà remboursé 30 M XAF. L'exposition restante est de 70 M XAF.

{% set EXP_TECH %}

L'exposition d'un prêt est l'encours restant dû (loans.outstanding_amount), jamais le capital initial. L'exposition du portefeuille est la somme des encours des prêts actifs. Implémentation : app/metrics.py, alimentée par la vue v_loans_enriched.

{% endset %} {{ deftech("Exposition", EXP_TECH) }}

⚠️ NPL — prêts non performants

NPL = Non-Performing Loan — prêt dont le remboursement est en difficulté.

Quelle partie du portefeuille présente un niveau de difficulté important ?

Un prêt est considéré comme non performant lorsqu'il présente un retard de paiement important. Dans cette démonstration, le seuil utilisé est de 90 jours de retard.

Exemple

Si 6 M XAF sur 100 M XAF d'encours correspondent à des prêts non performants, le ratio NPL est de 6 %. À titre d'illustration, le portefeuille de démonstration affiche un NPL autour de 5 % à la date de référence.

{% set NPL_TECH %}

NPL Ratio = Σ des encours des prêts dont le retard est ≥ 90 j au mois de référence (statuts actif, défaut, annalisé) divisé par l'exposition des prêts actifs. Sources : loan_monthly (fait mensuel au niveau prêt) et v_kpi_monthly (série mensuelle agrégée).

{% endset %} {{ deftech("NPL", NPL_TECH) }}

⏱️ DPD — retard de paiement

DPD = Days Past Due — nombre de jours écoulés depuis la date à laquelle un paiement aurait dû être effectué.

Le DPD est la brique de base de toutes les analyses de retard : il permet de savoir si un prêt est à jour, légèrement en retard, ou franchit les seuils de surveillance.

{% set DPD_TECH %}

Chaque paiement porte un days_past_due (paiement − échéance). Un état mensuel par prêt est stocké dans loan_monthly avec un bucket normalisé : CURRENT, 1-30, 31-60, 61-90, 90+. Risk Analytics et les alertes SAP exploitent ces buckets.

{% endset %} {{ deftech("DPD", DPD_TECH) }}

💳 Taux de paiement

Les emprunteurs paient-ils les montants qui arrivent à échéance ?

Cet indicateur compare les montants effectivement payés aux montants qui étaient dus. Un taux proche de 100 % signale un portefeuille à jour à la date de référence.

Exemple

Échus à la date de référence : 10 M XAF. Payés : 9,5 M XAF. Taux de paiement = 95 %.

{% set PAY_TECH %}

Taux de paiement = Σ des montants payés / Σ des montants échus à la date de référence (AS_OF_DATE = 2026-08-31), calculé sur les paiements des prêts actifs, clôturés et en défaut.

{% endset %} {{ deftech("Taux de paiement", PAY_TECH) }}

🚨 Défaut

Dans cette démonstration, un prêt bascule en défaut lorsqu'il franchit le seuil de retard défini par la méthodologie (≥ 90 jours de DPD). Il conserve ensuite ce statut jusqu'à la date de référence — c'est aussi la définition utilisée par l'indicateur de taux de défaut sur 12 mois glissants.

{% set DEF_TECH %}

Taux de défaut 12 mois = nombre de prêts (parmi ceux actifs 12 mois plus tôt) qui ont franchi ≥ 90 jours de DPD au cours des 12 derniers mois, divisé par le nombre de prêts actifs 12 mois plus tôt. Calcul sur la table de faits loan_monthly.

{% endset %} {{ deftech("Défaut et taux de défaut 12 mois", DEF_TECH) }}

🎯 Concentration du portefeuille

Le risque est-il réparti ou concentré sur quelques secteurs, pays ou emprunteurs ?

Imaginez un portefeuille de 100 prêts. Si les prêts sont répartis entre de nombreux secteurs, un problème dans un seul secteur aura un impact limité. Si une grande partie du portefeuille est concentrée dans un seul secteur, le même problème peut avoir un impact bien plus important.

HHI — Herfindahl-Hirschman Index

Le HHI est une mesure statistique utilisée ici pour mesurer le niveau de concentration du portefeuille : plus il est élevé, plus le risque dépend de quelques grandes expositions.

Limite — secteur unique
≤ 25 % de l'exposition du pays. Au-delà : DÉPASSEMENT.
Limite — emprunteur unique
≤ 2 % de l'encours total. Au-delà : DÉPASSEMENT.
{% set HHI_TECH %}

HHI = Σ (partᵢ² × 10 000), calculé sur les parts d'exposition par secteur et par pays. Implémentation : app/routes/risk.py. Suivi des limites avec statuts OK (secteur ≤ 20 %, emprunteur ≤ 1,6 %), VIGILANCE, DÉPASSEMENT (> 25 % / > 2 %).

{% endset %} {{ deftech("HHI et limites réglementaires", HHI_TECH) }}

Comment fonctionne le score de risque ?

Un score de risque résume plusieurs caractéristiques d'un emprunteur dans un indicateur unique. CreditRisk360 combine plusieurs facteurs liés au comportement de crédit afin de produire un score explicable, compris entre 300 et 850.

{% set pills = [ ("Historique de paiement", "bg-kpi-green-bg text-kpi-green-fg"), ("Retards", "bg-kpi-amber-bg text-kpi-amber-fg"), ("Défauts", "bg-kpi-red-bg text-kpi-red-fg"), ("Restructurations", "bg-kpi-purple-bg text-kpi-purple-fg"), ("Niveau d'endettement", "bg-kpi-blue-bg text-kpi-blue-fg"), ("Ancienneté · Demandes", "bg-kpi-green-bg text-kpi-green-fg"), ] %} {% for label, cls in pills %} {{ label }} {% if not loop.last %}+{% endif %} {% endfor %} → SCORE 300-850

L'objectif n'est pas de remplacer l'analyse humaine, mais de fournir un indicateur comparable et interprétable: chaque contribution est détaillée sur la fiche de chaque emprunteur et sur la page Scoring explicable.

{% call accordion("🔬 Pour les lecteurs techniques — voir le calcul détaillé") %}

Formule canonique

Score = 300 + 550 × Σ (Poidsᵢ × Sous-scoreᵢ), avec Sous-scoreᵢ ∈ [0, 1]

Poids des sous-scores

  • Historique de paiement — 0,35 (ratio payé/échu 12 m, pénalisé par le DPD récent)
  • Niveau d'endettement — 0,20 (encours comparé à une capacité dépendant du type d'emprunteur)
  • Antécédents de défaut — 0,15 (défauts et restructurations passées)
  • Ancienneté de relation — 0,10 (plafonnée à 8 ans)
  • Nouveaux crédits — 0,10 (prêts ouverts depuis moins de 6 mois)
  • Pression des demandes — 0,10 (consultations bureautiques sur 12 mois)

Bande de risque du score final

Faible ≥ 730 · Modéré ≥ 650 · Élevé ≥ 570 · Très Élevé < 570.

Contributions

Chaque facteur produit 550 × poids × sous-score points, comparés au profil moyen du portefeuille (les sous-scores moyens sont calculés sur un échantillon d'emprunteurs). Entrées : vue v_borrower_metrics.

{% endcall %}

Avant d'analyser le risque, il faut pouvoir faire confiance aux données

Une analyse de risque n'est fiable que si les données utilisées sont suffisamment cohérentes. Une échéance incohérente, un montant négatif ou un statut incorrect peut fausser les indicateurs. CreditRisk360 intègre donc une couche de Data Quality pour identifier et suivre certains problèmes.

Le statut des dossiers est persisté dans app_state_dq_resolutions et le bouton « Relancer la validation » recalcule les scores en direct.
